## October 16 search ranking — 0.14.20-owned / 34

Live searches showed Bandcamp tributes and alphabetical library tracks displacing Apple's relevant results. Three causes: (1) the server skipped a provider's whole album/track search when the library had one exact match; (2) the server dropped provider copies already in the library, losing their catalog rank, then interleaved alphabetical library results first; (3) web scoring (+300 library boost on artist-only matches, library-first ties) and Android (`sortedByDescending { isOwnedItem }`) re-sorted the server order. Bandcamp purchases counted as library. Backend `search-ranking-210f4ce5731b0f09` (controller.py + unified_search.py): artist-only exact-match shortcut, library copies substituted at the provider's rank, relevance scoring (exact title, exact artist, album, all words; library bonus only for exact titles), Bandcamp after major catalogs at equal relevance, merged cards show the Apple copy, combined cache key v4. Web 8d2a86d838a50054 changes three served assets (no library boost for artist-only matches, equal scores keep server order). Android keeps server order (`searchResultsFrom`). Tests: 10 ranking + 62 backend regressions + 8 search-background; 3036 web; 662 composeApp + 117 selected androidApp. Evidence: `../../evidence/20261016-search-ranking/`.
